# 文档目录、当前计划与证据

本规则负责文档的归属、布局、更新和迁移，不改变已确认目标、任务粒度、授权或验收标准。优先遵守明确的项目规范；建立或统一文档结构时采用下列紧凑布局，日常功能实施不顺带发起全仓目录迁移。

## 1. 按职责建立目录

| 目录 | 正文职责 | 生命周期 |
| --- | --- | --- |
| `docs/design/` | 长期系统架构、领域模型和 ADR；以导航区分文档职责 | 持续维护，失效或被替代时归档 |
| `docs/specs/` | 需求目标、范围、行为、兼容约束与验收合同 | 按需求合同的适用性独立判断归档 |
| `docs/tasks/` | 当前执行计划、依赖、完成条件、状态、阻塞与最新证据指针 | 完整范围与必要验收完成后归档 |
| `docs/guides/` | 使用、开发、部署、维护、备份与恢复说明 | 保持当前操作可用 |
| `docs/reviews/` | 审查判断、差异分析、决策依据与审查结论 | 结案后归档，当前任务仍可引用历史结论 |
| `docs/evidence/` | 实施记录、验证报告、原始材料、截图、固定样本与可重复基准 | 活动或共享证据保持单一正文与稳定路径 |
| `docs/archive/` | 已完成任务、失效合同、历史设计、结案报告与独占历史证据 | 保存历史，不能充当当前状态或新实施合同 |

按实际内容创建，不要求每个仓库都有全部目录。先通过同一目录的导航分组，不为少量架构、领域、ADR、工程或运维文件增加顶层目录。`docs/README.md` 负责入口；无活动任务时可直接说明当前无任务，不创建仅用于空状态的任务目录或索引。已有工具约定文件和明确的项目布局继续遵守。

长期设计与 Spec 分别维护：设计文档拥有当前运行链、术语、不变量和长期决策；Spec 拥有本主题的需求与验收，可保留必要方案与决策依据并链接长期设计。实施完成不自动使 Spec 失效，持续维护设计也不阻止已完成 Task 归档。只有已确认延期且不属于当前完成条件的实现才进入 TODO。

## 2. 当前计划、记录与证据

| 文档 | 应维护的内容 | 不应承担的内容 |
| --- | --- | --- |
| Task | 当前范围和执行包、稳定任务 ID、依赖、写集、完成条件、当前状态、精确阻塞、下一步、最新证据链接 | 历次检查点、完整命令输出、全量写集和不断追加的阶段报告 |
| 实施日志 | 按日期和任务 ID 保存实施批次、方案调整依据、授权事件、交接及结果变化，并引用详细证据 | 第二套当前任务表、活动计划或新的验收标准 |
| 验证报告 | 门禁断言、输入与版本、实际过程、结果、失败与修正、环境及未覆盖范围 | 代替 Task 决定当前状态，或以历史通过断言当前仍通过 |
| Review | 审查发现、差异、依据与结论，链接 Task 中的责任项和独立证据 | 复制完整进度表、原始输出或另一套未决任务清单 |

Task 是当前执行状态的唯一责任入口；顶部摘要只概括其任务和门禁，不计算另一套进度。日志和报告保存有日期及基线的观察，不拥有另一套当前状态。最终 Review 的最新结论和未解决责任留在 Task，详细发现由关联报告保存。

无明确项目约定时，支持文件使用独立证据目录，例如：

```text
docs/design/<topic>.md
docs/specs/YYYY-MM-DD-<task-id>.md
docs/tasks/<task-id>.md
docs/evidence/<task-id>/implementation-log.md
docs/evidence/<task-id>/<gate-or-topic>.md
docs/reviews/YYYY-MM-DD-<topic>.md
```

示例不是要求生成的文件清单。已有扁平日期文件可继续使用；仅在确有内容时创建支持文件。短日志可以包含简短验证记录，细节较多时再拆为报告。可重复基准可放在 `docs/evidence/benchmarks/`，不另建顶层分类。

按有意义的实施批次、门禁或主题组织记录，不按每个命令、工具调用或重试拆文件。证据独立于 Task 和 Review；共享证据只保留一份。已结案且仅属于归档任务的证据使用 `docs/archive/evidence/`，不要复制或重新拼回 Task。

## 3. Task 保持可直接执行

顶部维护最近核对时间、当前实施与验收概况、当前执行叶、阻塞或下一可执行叶；必要时补充当前授权边界与资源归属。进度变化时原位替换，不在末尾追加另一份“最新状态”。

执行叶保留 `task-planning.md` 要求的完整执行包：AC、启动依赖、必要上下文、可写范围与排除项、完成条件和验证方式。未完成的执行契约不能移入历史。执行后只更新最新结果、未满足条件与证据链接；完整实际写集、命令和历次尝试进入证据记录。

共享门禁在一个权威条目维护，其他任务引用；父分组不与子叶重复计数。已完成叶可保留简短结论和证据链接，恢复、审查或兼容仍需要的执行契约继续保留。

当前状态出现矛盾版本、阶段汇报掩盖任务定义，或必须读到日志末尾才知道下一步时，按职责整理。不能按行数机械切割，也不能因此新增产品范围或缩减必要实施。

## 4. 检查点与恢复

1. 写前重读受影响 Task 与关联记录，核对并行修改及写入归属。子执行者只写分配的报告，由指定维护者对账 Task。
2. 有价值的实施事实写入证据日志或报告，绑定日期、任务/AC、代码基线和环境。失败与修正保持可追溯，正文只维护一份。
3. 原位更新当前结果、门禁和摘要，链接本次适用证据。历史记录保存授权范围及使用/恢复结果；当前入口保留仍有效的边界，不延续已用完的一次授权。
4. 核对证据适用性、链接和下一叶。只有输入变化使证据失效时才重开受影响门禁；路径移动不证明任务完成，也不自动使证据失效。

记录已写入但 Task 因冲突尚未更新时，明确说明未对账。恢复时先读 Task 的当前摘要、执行叶与最新证据，再按问题读取历史。新的需求与验收决定回写 Spec；长期架构、领域与 ADR 更新其设计正文并由 Spec 引用；不能只藏在日志或对话里。

### 实施记录示例

```md
## 2026-10-11 / T3 / 缓存隔离验证

- 对应任务：[当前 Task](../../tasks/<task-id>.md) `T3`；验收断言：AC2
- 当时基线与范围：<代码/未提交工作区、环境与本批变更边界>
- 过程与决定：<必要的失败、修正和授权依据；新增工作标明原 AC、前置/缺陷或明确扩围依据>
- 当次结果与证据：<结果及报告链接>
- 当时未覆盖：<仍需验证的层级；当前状态回查 Task>
```

### 证据报告最小内容

```md
# <门禁或主题>验证记录

对应 Task：<相对链接>；任务/门禁：<稳定 ID>；断言：<AC 及具体行为>

## <日期或基线标识>

- 输入：<代码/工作区版本、必要配置与目标运行态；不包含密钥>
- 变更范围：<实际写集或可定位的变更引用>
- 验证：<实际命令/操作与关键断言；区分 fixture、集成、实源、浏览器等层级>
- 结果：<通过/失败/未执行/阻塞/不适用及原因；跳过项不计通过>
- 修正与复验：<原失败、修正及受影响复验，无则省略>
- 证据边界：<未证明的行为/环境；原始材料位置及可用性>
```

临时路径只能辅助定位，不能成为完成结论的唯一依据。必要事实保存在仓库报告或获准的持久材料中；凭据、大型原始日志、业务备份和应忽略的生成物不因此进入 Git。证据缺失或不可访问时明确记录，不补造结果。

## 5. 已有文档迁移与核对

在用户授权的整理范围内执行，不顺带重排产品计划或改动运行配置。

1. 保留写前清单与对照：路径、文档职责、任务/AC、勾选、依赖、未解决义务、授权边界、证据及入站引用。核对并行写入；不要仅凭日期、过期页头或勾选数量判断归档。
2. 建立明确的旧路径到新路径映射，按职责移动原文。分离混合段落，当前执行定义、门禁与未决要求留在 Task；历史记录保留日期、原结论和适用基线。导航合并后仍须能找到全部责任入口。
3. 纯目录迁移不改变验收含义。状态确有错误时单独说明对账依据；不能把状态修正、取消义务或 TODO 转移藏在搬迁里。
4. 修复双向链接、相对路径、跨仓引用和原有效锚点；同时检查实际读取文件的脚本、测试、清单、CI、挂载和打包输入。只改路径消费者，不因移动重写已执行的历史命令或冻结事实。
5. 原始响应、签名、摘要样本和冻结记录保持字节；历史 `source.references` 等来源字段按当时语义保留。需要当前查阅位置时用导航或对应报告说明。
6. 检查新路径的 Git 跟踪与忽略状态。正式文档被旧的整目录规则误排除时，在授权范围内精准修正规则；不能强行纳入凭据、生成物或私有证据。交付包含提交时，从暂存区或提交树再次检查文档目标，不能只凭本地文件存在判定引用完整。
7. 对照任务/AC、依赖、授权、未完成义务、原有效锚点和证据，验证全部保留且没有重复责任清单。复用输入未变的已有验证，只重跑受路径影响的消费者检查；区分文档完整性与产品运行验收。

无法修复的外部引用或无法核验的证据要明确列出缺口，按项目已有的兼容规则处理，不能制造第二份活动 Task。已归档 Task 的入站引用直接指向归档正文，原路径默认移除；具体兼容要求按项目规则及 `archive-handling.md` 处理。历史日志从 Task 拆出不等于 Task 已归档，未完成范围继续保持活动责任。

# Codex GPT-6 迁移与运行时检查

仅在升级、模型路由异常、并发限制或上下文隔离不符合预期时读取。这里是配置说明，不会自动修改本机配置，也不额外引入运行时控制器。

## 模型与角色

GPT-6 环境可使用实际可用的 `gpt-6-luna`；父代理继续使用用户选择的模型，不绑定为 Sol。升级时检查自定义角色实际加载的 `model` 和 `model_reasoning_effort`，不要只凭 `luna_worker` 这个名字判断模型。

当前官方文档说明：自定义 agent 文件中的显式模型/推理设置会覆盖此前解析的设置。因此，即使 spawn 请求了新模型，旧角色文件仍可能把它覆盖回旧模型。缺少子代理模型设置时也可能继承父模型；必须核对实际配置，而不是仅修改 skill 描述。保留用户明确指定的推理档位，仅使用所选模型支持的值。[1]

## 并发容量与任务隔离

本 skill 不再设置固定的单 worker 上限。实际并发仍受用户约束和运行时配置限制：`agents.max_concurrent_threads_per_session` 限制同时打开的子代理线程，不包含主线程；未设置时由 Codex 选择默认值。`agents.max_threads` 是旧别名，不能同时设置互相冲突的值。[2]

迁移时检查是否仍有旧配置将并发限制为单线程；如需调整，按用户授权修改或移除该限制，而不是在 skill 中另行写死一个并发数量。任务完成或安全交接后关闭对应线程以释放槽位，独立任务不必等待其他 worker 全部关闭。

worker 自身可通过其配置中的 `[agents] enabled = false` 禁用多代理工具，以配合不允许嵌套委派的规则。[2] 不要把它误设到需要调度 worker 的父代理配置中。

并发容量不等于可以安全并行。每个任务先声明可写路径、稳定只读输入、依赖和共享资源；同一文件只允许一个活跃写入者，不能因修改不同行或使用不同 worktree 就放开重复写入。公共类型、锁文件、导出入口、生成产物和共享测试资源必须明确归属或隔离。无法确定安全边界时，只串行受影响的任务。

父代理独占更新共享任务清单，worker 的报告与证据写入各自任务目录。隔离 worktree 的产物必须经过有界集成任务进入目标工作区后，依赖它们的任务才能启动；共享集成目标同一时刻只有一个写入者。最终验证与 review 针对记录下来的稳定状态，不在未完成的并发改动上出验收结论。以上是工作流约束，不代表运行时自动提供文件锁。

## 新线程与干净上下文

执行前检查当前实际暴露的创建线程工具及其参数。只使用当前运行时明确支持的不继承历史模式；不要把可能存在的工具参数当作通用 `config.toml` 配置项。

创建新线程、关闭旧线程、不复用会话，是 skill 的调度要求；能否禁止继承父对话，仍取决于运行时。无法确认时如实报告，不能用“忽略之前内容”的提示词冒充物理隔离，也不能承诺新建 agent ID 就一定得到干净上下文。

模型上下文长度、自动压缩或实验性记忆不能替代持久任务清单。跨 worker 只传递当前任务、必要契约和产物位置；代码与已有用户改动留在正确的工作区。

## 验收场景

升级后用一个小任务组观察实际轨迹，而不只检查文档：

- 两个依赖已满足、写集和资源不冲突的非视觉任务使用不同新线程并行；可复用相同模型/角色，完成后各自关闭。
- 两个任务要求修改同一文件（包括不同代码段或不同 worktree），或共享锁文件、快照、测试数据库时，先拆分、指定独占 owner 或隔离资源；边界未解决前不得同时写入。
- 公共契约先落实，再并行实现写集分离的 API 与客户端任务；下游不得读取上游正在修改的文件。契约变化、失败依赖或越界会暂停受影响任务，不妨碍无关任务继续。
- worker 不并发修改共享任务清单；取消 worker 后，确认其写入进程停止并记录交接，才转移文件或资源归属。
- 视觉任务使用非 Luna worker；满足相同独立性条件时可与非视觉任务并行，所有 worker 都不再委派。
- 普通成功返回后父代理只更新状态、归属和调度；产物集成后在稳定状态上运行验证，最后统一 review；修复使用新 worker，不恢复旧会话。
- 通过客户端可观察的线程配置或创建参数核实历史继承行为；看不到证据时不得标记上下文隔离已验证。

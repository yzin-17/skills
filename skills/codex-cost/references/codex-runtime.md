# Codex GPT-6 迁移与运行时检查

仅在升级、模型路由异常、并发限制或上下文隔离不符合预期时读取。这里是配置说明，不会自动修改本机配置，也不额外引入运行时控制器。

## 模型与角色

GPT-6 环境可使用实际可用的 `gpt-6-luna`；父代理继续使用用户选择的模型，不绑定为 Sol。升级时检查自定义角色实际加载的 `model` 和 `model_reasoning_effort`，不要只凭 `luna_worker` 这个名字判断模型。

当前官方文档说明：自定义 agent 文件中的显式模型/推理设置会覆盖此前解析的设置。因此，即使 spawn 请求了新模型，旧角色文件仍可能把它覆盖回旧模型。缺少子代理模型设置时也可能继承父模型；必须核对实际配置，而不是仅修改 skill 描述。保留用户明确指定的推理档位，仅使用所选模型支持的值。[1]

## 单 worker 限制

当前配置项限制同时打开的子代理线程，不包含主线程：[2]

```toml
[agents]
max_concurrent_threads_per_session = 1
```

`agents.max_threads` 是旧别名。只在所用客户端支持时采用新键，不要重复设置互相冲突的值。每个任务结束后关闭线程、释放槽位，再创建下一个；“最多一个”不是整个任务只能创建一个 worker。

worker 自身可通过其配置中的 `[agents] enabled = false` 禁用多代理工具，以配合不允许嵌套委派的规则。[2] 不要把它误设到需要调度 worker 的父代理配置中。

## 新线程与干净上下文

执行前检查当前实际暴露的创建线程工具及其参数。只使用当前运行时明确支持的不继承历史模式；不要把可能存在的工具参数当作通用 `config.toml` 配置项。

创建新线程、关闭旧线程、不复用会话，是 skill 的调度要求；能否禁止继承父对话，仍取决于运行时。无法确认时如实报告，不能用“忽略之前内容”的提示词冒充物理隔离，也不能承诺新建 agent ID 就一定得到干净上下文。

模型上下文长度、自动压缩或实验性记忆不能替代持久任务清单。跨 worker 只传递当前任务、必要契约和产物位置；代码与已有用户改动留在正确的工作区。

## 验收场景

升级后用一个小任务组观察实际轨迹，而不只检查文档：

- 两个连续非视觉任务使用相同模型/角色、不同线程；先关闭第一个，再创建第二个。
- 中间插入视觉任务时使用非 Luna worker，仍然串行；所有 worker 都不再委派。
- 普通成功返回后父代理只更新状态并继续；失败依赖会阻止其下游任务启动。
- 最后统一检查真实 diff 和集成证据；发现问题时新建修复 worker，不恢复旧会话。
- 通过客户端可观察的线程配置或创建参数核实历史继承行为；看不到证据时不得标记上下文隔离已验证。
